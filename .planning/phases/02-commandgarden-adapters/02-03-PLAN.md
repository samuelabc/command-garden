### Task 2: Create eval script

<read_first>
- `commandGarden/connectors/teams-room-availability.eval.js` (browser session pattern reference)
</read_first>

<action>
Create `commandGarden/connectors/jira-my-tickets.eval.js`:
1. Wait for SSO redirect to land on `mercedes-benz.atlassian.net` (up to 30s)
2. Read args: `fromDate`, `toDate`, `assignee` (defaults to Jira's `currentUser()` JQL function)
3. Run 2 JQL queries in parallel via Jira REST API v3 (`/rest/api/3/search`):
   - Resolved: `assignee = currentUser() AND status changed TO ("Done","Closed","Resolved") DURING ("fromDate","toDate")`
   - In-progress: `assignee = currentUser() AND status IN ("In Progress","In Review","To Do","Open")`
4. Auth: `credentials: 'include'` sends Atlassian session cookies (same-origin fetch)
5. Calculate staleDays for in-progress items from `updated` field
6. Determine category: `"resolved"` | `"inProgress"` | `"blocker"` (staleDays >= 3)
7. Build and return rows with Jira field names (`key`, `summary`, `status`)
</action>

<acceptance_criteria>
- Script uses Atlassian session cookies (no MSAL/PAT)
- Runs JQL queries via Jira REST API v3
- Calculates staleDays from `updated` field
- Categories: resolved, inProgress, blocker
- Defaults to `currentUser()` JQL function when no assignee provided
- Returns array matching YAML columns (key, summary, status, type, etc.)
</acceptance_criteria>

</verify>
