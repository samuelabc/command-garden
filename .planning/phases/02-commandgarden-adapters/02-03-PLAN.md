<objective>
Build a commandGarden YAML connector + eval script for Jira/ADO Work Items that extracts tickets assigned to the user via browser session MSAL token (no PAT required). Uses the same ADO Work Items WIQL API as the Phase 1 jira.source.ts but authenticates via the browser's SSO session. Named "jira" for future migration compatibility, currently backed by ADO Boards.
</objective>

### Task 2: Create eval script

<read_first>
- `commandGarden/connectors/ado-git-commits.eval.js` (MSAL token pattern — same domain)
- `commandGarden/connectors/lib/msal-token.js` (token polling snippet)
- `dashboard/api/src/journal/sources/jira.source.ts` (WIQL queries to port)
</read_first>

<action>
Create `commandGarden/connectors/jira-my-tickets.eval.js`:
1. MSAL token polling (copy from `lib/msal-token.js`)
2. Read args: `fromDate = '${{ args.fromDate }}'`, `toDate = '${{ args.toDate }}'`, `assignee = '${{ args.assignee | default("") }}'`
3. If no assignee, detect current user from MSAL token claims (parse JWT payload for `upn` or `unique_name`)
4. Run 2 WIQL queries in parallel:
   - Resolved: `SELECT [System.Id] FROM WorkItems WHERE [System.AssignedTo] = '${assignee}' AND [System.State] IN ('Resolved','Closed','Done') AND [Microsoft.VSTS.Common.ResolvedDate] >= '${fromDate}' AND [Microsoft.VSTS.Common.ResolvedDate] <= '${toDate}'`
   - In-progress: `SELECT [System.Id] FROM WorkItems WHERE [System.AssignedTo] = '${assignee}' AND [System.State] IN ('Active','In Progress','Doing')`
5. Batch-fetch work item details for both sets: `GET /_apis/wit/workitems?ids=...&fields=System.Id,System.Title,System.State,System.WorkItemType,Microsoft.VSTS.Common.ResolvedDate,Microsoft.VSTS.Common.StateChangeDate&api-version=7.1`
6. Calculate staleDays for in-progress items: `Math.floor((Date.now() - new Date(stateChangeDate)) / 86400000)`
7. Determine category: `"resolved"` | `"inProgress"` | `"blocker"` (in-progress + staleDays >= 3)
8. Build and return rows
</action>

<acceptance_criteria>
- Script polls for MSAL token
- Runs WIQL queries for resolved and in-progress work items
- Batch-fetches work item details
- Calculates staleDays from StateChangeDate
- Categories: resolved, inProgress, blocker
- Auto-detects assignee from JWT when not provided
- Returns array matching YAML columns
</acceptance_criteria>
