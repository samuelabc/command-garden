<objective>
Build a commandGarden YAML connector + eval script for Azure DevOps Git that extracts commits and PRs via browser session MSAL token (no PAT required). Uses the same ADO Pushes API as the Phase 1 git.source.ts but authenticates via the browser's SSO session instead of a personal access token.
</objective>

<tasks>

### Task 1: Create YAML connector definition

<read_first>
- `commandGarden/connectors/timetracking-report.yaml` (pattern reference)
</read_first>

<action>
Create `commandGarden/connectors/ado-git-commits.yaml`:
- `site: ado`, `name: git-commits`, `version: "1.0"`
- `description: "Azure DevOps Git commits and PRs across all branches for a date range"`
- `access: read`
- `domains: ["dev.azure.com"]`
- `capabilities: [navigate, js_evaluate]`
- `args`: `project` (string, required), `repo` (string, required), `fromDate` (string, required, pattern `^\d{4}-\d{2}-\d{2}$`), `toDate` (string, required, same pattern), `author` (string, optional, help "Filter by pusher name/email")
- `columns`: `commitId` (string), `authorName` (string), `authorEmail` (string), `date` (string), `message` (string), `filesAdded` (number), `filesEdited` (number), `filesDeleted` (number), `isPR` (string), `prId` (number)
- `pipeline`: navigate to `https://dev.azure.com/${{ args.project }}`, wait for body (30s), js_evaluate with `ado-git-commits.eval.js`
</action>

<acceptance_criteria>
- YAML file exists at `commandGarden/connectors/ado-git-commits.yaml`
- `site: ado`, `name: git-commits`
- Has 5 args: project, repo, fromDate, toDate, author
- Has 10 columns matching the output schema
- Pipeline has 3 steps: navigate, wait, js_evaluate
</acceptance_criteria>

### Task 2: Create eval script

<read_first>
- `commandGarden/connectors/timetracking-report.eval.js` (MSAL token pattern)
- `commandGarden/connectors/lib/msal-token.js` (token polling snippet)
- `dashboard/api/src/journal/sources/git.source.ts` (API logic to port)
</read_first>

<action>
Create `commandGarden/connectors/ado-git-commits.eval.js`:
1. MSAL token polling (copy from `lib/msal-token.js`)
2. Read args: `project = '${{ args.project }}'`, `repo = '${{ args.repo }}'`, `fromDate = '${{ args.fromDate }}'`, `toDate = '${{ args.toDate }}'`, `author = '${{ args.author | default("") }}'`
3. Construct API base: `https://dev.azure.com/${project}/_apis`
4. Fetch pushes: `GET /git/repositories/${repo}/pushes?searchCriteria.fromDate=${fromDate}T00:00:00Z&searchCriteria.toDate=${toDate}T23:59:59Z&api-version=7.1`
5. Filter pushes by author (if provided): compare `pushedBy.uniqueName` and `pushedBy.displayName` against author (case-insensitive includes)
6. Fetch each push detail: `GET /git/repositories/${repo}/pushes/${pushId}?api-version=7.1`
7. Deduplicate commits by commitId
8. Fetch completed PRs: `GET /git/repositories/${repo}/pullrequests?searchCriteria.status=completed&api-version=7.1`, filter by closedDate in range
9. Build rows: one per commit + one per PR (set `isPR: "true"` for PR rows)
10. `return rows;`
</action>

<acceptance_criteria>
- Script polls for MSAL token (60s deadline)
- Calls ADO Pushes API with auth header `Bearer ${token}`
- Filters by author when provided
- Deduplicates commits by commitId
- Fetches completed PRs separately
- Returns array of row objects matching YAML columns
- Template variables: `${{ args.project }}`, `${{ args.repo }}`, etc.
</acceptance_criteria>
