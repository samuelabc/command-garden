<objective>
Build a commandGarden YAML connector + eval script for Outlook Calendar that extracts the user's own meeting schedule via browser automation. Reuses the existing teams/room-availability approach — navigates to OWA Scheduling Assistant, intercepts `getSchedule` GraphQL calls, and captures the organizer's own scheduleItems (meetings, free/busy blocks).
</objective>

<tasks>

### Task 1: Create YAML connector definition

<read_first>
- `commandGarden/connectors/teams-room-availability.yaml` (pattern reference — same domain)
</read_first>

<action>
Create `commandGarden/connectors/outlook-my-meetings.yaml`:
- `site: outlook`, `name: my-meetings`, `version: "1.0"`
- `description: "User's own meeting schedule from Outlook Calendar for a given day"`
- `access: read`
- `domains: ["outlook.cloud.microsoft.mcas.ms"]` (same domain as room-availability)
- `capabilities: [navigate, js_evaluate]`
- `args`: `date` (string, required, pattern `^\d{4}-\d{2}-\d{2}$`, help "Day to fetch in YYYY-MM-DD format")
- `columns`: `date` (string), `subject` (string), `start` (string), `end` (string), `durationMin` (number), `state` (string)
- `pipeline`: navigate to `https://outlook.cloud.microsoft.mcas.ms/calendar/deeplink/compose`, wait for body (30s), js_evaluate with `outlook-my-meetings.eval.js`
</action>

<acceptance_criteria>
- YAML file at `commandGarden/connectors/outlook-my-meetings.yaml`
- `site: outlook`, `name: my-meetings`
- Domain matches existing room-availability connector
- 1 required arg: date
- 6 columns: date, subject, start, end, durationMin, state
</acceptance_criteria>

<verify>
```bash

grep "my-meetings" commandGarden/connectors/outlook-my-meetings.yaml
```
</verify>

### Task 2: Create eval script

<read_first>
- `commandGarden/connectors/teams-room-availability.eval.js` (heavily reusable — same OWA UI flow)
</read_first>

<action>
Create `commandGarden/connectors/outlook-my-meetings.eval.js`. Reuse significant portions of `teams-room-availability.eval.js`:

1. Copy shared helpers: `pad2`, `sleep`, `todayLocalISO`, `dateCellLabel`, `$`, `exists`, `clickByName`, `schedulingAssistantOpen`, `typeText`
2. Copy the fetch interceptor (captures `getSchedule` GraphQL responses)
3. Copy `schedulesFromPair` and `buildTimeline` functions
4. Read arg: `date = '${{ args.date }}'`
5. Wait for compose form controls (handles SSO redirect delays)
6. Open the Scheduling Assistant
7. Set the date using the calendar picker (same logic as room-availability)
8. **Key difference:** Do NOT add a room or attendee. The organizer's own schedule loads automatically when the Scheduling Assistant opens.
9. Capture the organizer's scheduleItems from intercepted responses (the first/pre-existing schedule IDs belong to the organizer)
10. Build timeline using `buildTimeline` function
11. Return rows with: `date`, `subject` (from `scheduleItems[].subject` if available, else "(meeting)"), `start`, `end`, `durationMin`, `state`
12. Filter to only busy/tentative blocks (skip free blocks)
</action>

<acceptance_criteria>
- Script navigates to OWA calendar compose deeplink
- Opens Scheduling Assistant
- Sets the target date
- Does NOT add any attendee or room (captures organizer's own schedule)
- Captures getSchedule GraphQL responses via fetch interceptor
- Returns busy/tentative blocks as meetings
- Each row has: date, subject, start, end, durationMin, state
- Handles SSO redirect delays (up to 30s wait)
</acceptance_criteria>

<verify>
```bash

grep "subject" commandGarden/connectors/outlook-my-meetings.eval.js
grep "return" commandGarden/connectors/outlook-my-meetings.eval.js
```
</verify>
