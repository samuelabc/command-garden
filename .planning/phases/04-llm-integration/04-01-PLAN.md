<objective>
Replace the rule-based `generateBasicInsights()` method with an LLM-powered insights generator using the Anthropic Claude API. The LLM receives only aggregated counts and patterns (never raw content like meeting subjects, ticket titles, or commit messages) and produces 3-5 actionable weekly insights. Falls back to rule-based insights when the LLM is unavailable.
</objective>

<tasks>

### Task 1: Create LLM service module

<read_first>
- `commandGarden/app/src/server/journal/journal.service.ts` (current insights generation)
- `commandGarden/app/src/server/journal/journal.types.ts` (data shapes to summarize)
</read_first>

<action>
Create `commandGarden/app/src/server/journal/llm.ts`:

1. Read config: `ANTHROPIC_API_KEY` from env var, `LLM_MODEL` (default `claude-sonnet-4-20250514`)
2. Export `generateLLMInsights(summary: InsightsSummary): Promise<string[]>` function
3. Define `InsightsSummary` interface — the privacy-safe aggregated data sent to the LLM:
   ```typescript
   interface InsightsSummary {
     week: string;
     hoursLogged: number | null;
     targetHours: number | null;
     meetingCount: number | null;
     meetingHours: number | null;
     avgMeetingDurationMin: number | null;
     ticketsResolved: number | null;
     ticketsInProgress: number | null;
     ticketsBlocked: number | null;
     totalCommits: number | null;
     totalPRsMerged: number | null;
     forgottenDays: string[];      // dates only, no content
     heavyMeetingDays: string[];   // dates only
     zeroCodingDays: string[];     // dates only
     meetingRatio: number | null;
     codingHours: number | null;
   }
   ```
4. Build the prompt:
   - System: "You are a concise work-productivity advisor. Generate 3-5 actionable weekly insights from the aggregated data below. Each insight should be 1-2 sentences and suggest a concrete action. Never reference raw data you don't have — only use the aggregated metrics provided."
   - User: JSON.stringify(summary)
5. Call Anthropic API: `POST https://api.anthropic.com/v1/messages` with `x-api-key` header, `model`, `max_tokens: 500`, `messages`
6. Parse response: extract text content, split into individual insights (one per line or bullet)
7. Return `string[]` — the insights
8. On any error (missing API key, network failure, rate limit), return `null` so the caller falls back to rule-based insights
</action>

<acceptance_criteria>
- `llm.ts` exports `generateLLMInsights` and `InsightsSummary`
- Only sends aggregated counts/metrics to the LLM — no raw meeting subjects, ticket titles, or commit messages
- Uses `ANTHROPIC_API_KEY` from env var
- Returns `string[]` on success, `null` on failure
- Prompt instructs LLM to generate 3-5 actionable insights
- Max 500 tokens response
</acceptance_criteria>

<verify>
```bash

grep "InsightsSummary" commandGarden/app/src/server/journal/llm.ts
```

</verify>

<action>
Update `commandGarden/app/src/server/journal/journal.service.ts`:

1. Import `generateLLMInsights` and `InsightsSummary` from `./llm.js`
2. In `generate()`, after cross-reference is computed, build an `InsightsSummary` from the available data:
   - Map `TimetrackingData` → `hoursLogged`, `targetHours`
   - Map `MeetingsData` → `meetingCount`, `meetingHours`, `avgMeetingDurationMin`
   - Map `JiraData` → `ticketsResolved`, `ticketsInProgress`, `ticketsBlocked`
   - Map `GitData` → `totalCommits`, `totalPRsMerged`
   - Map `CrossRefData` → `forgottenDays`, `heavyMeetingDays` (dates only), `zeroCodingDays`, `meetingRatio`, `codingHours`
3. Try LLM insights first: `const llmInsights = await generateLLMInsights(summary)`
4. If LLM returns insights, use those. Otherwise fall back to `generateBasicInsights()` (existing rule-based method)
5. Keep `generateBasicInsights()` as-is for the fallback path — do NOT delete it
</action>

- `InsightsSummary` built from only aggregated data (no raw content)
- Existing `generateBasicInsights()` method preserved as fallback
- No change to the `JournalResponse` interface — insights are still `string[]`
</acceptance_criteria>
